# 多文档格式支持方案（编辑友好版）

## 1. 目标

支持编辑上传 **Word (.docx) / PDF / TXT / Markdown (.md)** 格式的小说文件，统一解析为内部结构化数据，后续管道完全复用。

```
上传文件 → 格式检测 → 解析为结构化文本 → 清洗 → 分块 → 编译 → 图谱
                     ↑  新增层  ↑       ↑ 已有逻辑，无需改动
```

---

## 2. 架构设计：策略模式

```
                    ┌─────────────┐
                    │  DocumentRouter  │   ← 入口：检测格式，分发解析器
                    └──────┬──────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌──────────┐    ┌──────────┐     ┌──────────┐
   │ TxtParser │    │ DocxParser│     │ PdfParser│    ← 可扩展
   └──────────┘    └──────────┘     └──────────┘
          │                │                │
          ▼                ▼                ▼
   ┌──────────────────────────────────────────┐
   │        统一输出: list[dict]               │
   │  [{"title": "第一章", "text": "..."}, ...]│
   └──────────────────────────────────────────┘
          │
          ▼
   ┌──────────────────────────────────────────┐
   │     已有管道 (clean_novel → chunker →    │
   │     chapter_parser → knowledge_graph)    │
   └──────────────────────────────────────────┘
```

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **加一层，不动旧层** | 新增 `DocumentRouter` + `Parser` 接口，现有 `clean_novel` 等逻辑不改 |
| **统一输出格式** | 所有 Parser 最终输出 `{"chapters": [{"title": str, "text": str}]}` |
| **插件式注册** | 新增格式只需实现一个 Parser 类，注册到 Router 即可 |
| **编辑友好** | Word 的跟踪修订、批注做特殊处理；PDF 保留段落结构 |

### 3.2 Word (.docx) ✅ 推荐首批支持

```python
class DocxParser(DocumentParser):
    extensions = [".docx"]

    def parse(self, filepath: str) -> dict:
        # 依赖 pip install python-docx
        from docx import Document

        doc = Document(filepath)
        full_text = []

        for para in doc.paragraphs:
            # 跳过图片/表格/批注框
            if para.style.name.startswith("Heading"):
                # 标题行标记为章节标题
                full_text.append(f"\n{para.text}\n")
            else:
                full_text.append(para.text)

        # 然后复用 extract_chapters() 检测章节边界
        return extract_chapters("\n".join(full_text))
```

**所需依赖**：`python-docx`（轻量，纯 Python，约 2MB）

**特点**：
- 保留标题样式 → 提高章节检测准确率
- 跳过图片/表格（网文罕见）
- 跟踪修订会自动合并为最终文字

### 3.3 PDF

```python
class PdfParser(DocumentParser):
    extensions = [".pdf"]

    def parse(self, filepath: str) -> dict:
        # 方案 A: pdfplumber（推荐，段落保留好）
        # pip install pdfplumber
        import pdfplumber

        with pdfplumber.open(filepath) as pdf:
            text = "\n".join(page.extract_text() or "" for page in pdf.pages)

        # 方案 B: PyMuPDF (fitz) 备选
        # import fitz
        # doc = fitz.open(filepath)
        # text = "\n".join(page.get_text() for page in doc)

        # 然后复用 extract_chapters()
        return extract_chapters(text)
```

**所需依赖**：`pdfplumber`（推荐）或 `PyMuPDF`（备选）

**注意**：
- 扫描版 PDF 无法提取文本（需要 OCR，不在范围内）
- 带目录的 PDF 可提取目录作为章节参照
- 两栏排版的 PDF 需要额外处理（`pdfplumber` 有内置排版分析）

### 3.4 Markdown (.md)

```python
class MarkdownParser(DocumentParser):
    extensions = [".md"]

    def parse(self, filepath: str) -> dict:
        # 保留标题行作为章节边界
        import re
        text = open(filepath, "r", encoding="utf-8").read()
        # 将 # 标题转为章节标题格式
        text = re.sub(r"^#+\s+", "", text, flags=re.MULTILINE)
        return extract_chapters(text)
```

**零依赖**，纯正则即可。

## 4. 编辑友好特性

### 4.1 Word 跟踪修订 / 批注

```python
# 处理修订（合并为最终文本）
doc = Document(filepath)
# python-docx 默认自动合并跟踪修订，无需额外操作
# 批注内容可通过 doc.comments 访问，可选择：
# - 保留为脚注
# - 完全忽略
```

### 4.2 PDF 乱码 / 编码问题

- `pdfplumber`：遇到乱码段落自动跳过 + 日志记录
- 降级回退：特殊字符替换为 □，保留全文结构

### 4.3 文件校验（复用 security.py）

```
格式检测 → 魔数验证（非仅扩展名）→ Parser 分发
```

已有的 `FileValidator` 已校验 MIME 类型和魔数，Parser 接收前就确保文件是合法格式。

### 4.4 错误处理规范

所有 Parser 统一错误行为：

```python
try:
    chapters = parser.parse(filepath)
except UnsupportedFormatError:
    # 返回友好提示："不支持此格式"
except CorruptedFileError:
    # "文件已损坏，请重新导出"
except Exception:
    # fallback: 尝试按纯文本读取
    text = filepath.read_text(errors="replace")
    chapters = extract_chapters(text)
```

## 6. 代码结构预览

```python
# core/document_parser.py

from abc import ABC, abstractmethod
from pathlib import Path


class DocumentParser(ABC):
    """文档解析器基类"""

    extensions: list[str] = []      # 支持的文件扩展名，如 [".docx", ".doc"]
    magic_bytes: list[bytes] = []   # 文件魔数，用于格式验证

    @abstractmethod
    def parse(self, filepath: str | Path) -> dict:
        """
        解析文档，返回统一格式:
        {
            "title": str,
            "chapters": [{"title": str, "text": str}, ...],
            "metadata": {"pages": int, "author": str, ...}
        }
        """
        ...


class DocumentRouter:
    """格式检测路由"""

    def __init__(self):
        self._parsers: dict[str, type[DocumentParser]] = {}

    def register(self, parser_cls: type[DocumentParser]):
        """注册解析器"""
        for ext in parser_cls.extensions:
            self._parsers[ext.lower()] = parser_cls

    def parse(self, filepath: str | Path) -> dict:
        """自动检测格式并解析"""
        ext = Path(filepath).suffix.lower()
        if ext not in self._parsers:
            raise UnsupportedFormatError(f"不支持的文件格式: {ext}")
        parser = self._parsers[ext]()
        return parser.parse(filepath)


# 默认注册
router = DocumentRouter()
router.register(TxtParser)       # 已有
# router.register(DocxParser)    # Phase 2 开启
# router.register(PdfParser)     # Phase 3 开启
# router.register(MarkdownParser) # Phase 4 开启
```

## 8. 不做的事情

| 功能 | 原因 |
|------|------|
| 扫描版 PDF OCR | 需要 Tesseract 二进制 + GPU，运维成本高 |
| EPUB 导入 | EPUB 是导出格式，导入场景极少 |
| 图片/漫画 | 不在网文分析范畴 |
| 网页抓取 | 这是版权问题，不在项目范围 |
| Excel/CSV 导入 | 人物清单可用作辅助数据，但非小说正文格式 |

## 9. 总结：编辑工作流变更

**之前**：
```
拿到 Word 稿件 → 另存为 TXT → 手动调整编码 → 上传 → 清洗
```

**之后**：
```
拿到 Word 稿件 → 直接上传 → 自动解析 → 清洗 → 编译
```

**编辑不需要关心**：
- 文件编码（所有 Parser 自动处理）
- 章节边界（Word 的 Heading 样式 / PDF 目录 / Markdown 的 # 号 = 自动章节检测）
- 特殊字符（自动转义 / 替换 / 跳过）
